# Eddy Current Implementation in KomaMRI - Supporting Document

## Architecture 
Implementing the capacity for eddy current simulations in the KomaMRI environment without introducing significant computational overhead required the following additions:
- '.../KomaMRIBase/src/datatypes/***EddyCurrents.jl***': contains the `calculate_eddy()` function which applies 0th, 1st, and 2nd-order eddy currents to a discrete sequence;
- '.../KomaMRIBase/src/datatypes/***DiscreteEddySequence.jl***': modified version of the `DiscreteSequence` struct which allows for eddy current compatibility;
- '.../KomaMRICore/src/simulation/SimMethods/Bloch/cpu/***BlochEddy.jl***': modified version of `BlochCPU` sim method which adds eddy current calculations.

The following files were also modified to allow for full integration:
- '...KomaMRICore/src/***KomaMRICore.jl***': added an export for the `BlochEddy` sim method;
- '...KomaMRICore/src/simulation/SimMethods/***SimulationMethod.jl***': added `include` line for sim method;
- '...KomaMRICore/src/simulation/***SimulatorCore.jl***': made `get_sim_ranges()` function compatible with new sequence type;
- '...KomaMRIBase/src/***KomaMRIBase.jl***': added `include` and `export` lines for new sequence type and eddy current function.

This implementation ensures complete backwards compatibility when eddy current modelling is disabled.

### EddyCurrents.jl
Transforms a standard `DiscreteSequence` by superimposing eddy current effects, outputting a `DiscreteEddySequence`.

```julia 
function calculate_eddy(seqd, τ, coefficients)
    [...]
    return DiscreteEddySequence(
        Gx_final, Gy_final, Gz_final,   # new arrays with 1st-order terms added
        seqd.B1, Δf_final, seqd.ψ, seqd.ADC, seqd.excitation_bool, t, seqd.Δt,
        Ez2, Ezx, Ezy, Exy, Ex2y2       # 2nd-order cross term arrays
    )
end
```
The time constant argument $\tau$ can be either a single value which is applied globally to all terms, or a vector of 9 values for assigning distinct time constants to each spatial term. Values should be in seconds.
The coupling coefficients argument requires a 9x3 array with this exact structure:

| Harmonic Order | Field Component | X Gradient Col 1 | Y Gradient Col 2 | Z Gradient Col 3 |
| :--- | :--- | :--- | :--- | :--- |
| **0th-Order** | **B0** | C[1,1] | C[1,2] | C[1,3] |
| **1st-Order** | **X** | C[2,1] | C[2,2] | C[2,3] |
| | **Y** | C[3,1] | C[3,2] | C[3,3] |
| | **Z** | C[4,1] | C[4,2] | C[4,3] |
| **2nd-Order** | **Z²** | C[5,1] | C[5,2] | C[5,3] |
| | **ZX** | C[6,1] | C[6,2] | C[6,3] |
| | **ZY** | C[7,1] | C[7,2] | C[7,3] |
| | **XY** | C[8,1] | C[8,2] | C[8,3] |
| | **X²-Y²** | C[9,1] | C[9,2] | C[9,3] |

For example, element `C[2, 3]` dictates the linear X eddy current field induced by the Z gradient coil.

***Physics Integration***
The `calculate_eddy` function operates by evaluating the derivative of the primary gradient waveforms to find the discrete amplitude steps ($dG_x, ~ dG_y, ~ dG_z$). Eddy currents are generated by these rapidly switching gradient steps. 
To calculate the accumulating error fields over time, the function utilises a recursive exponential decay model. For every time step, it applies an exponential decay curve ($e^{-\Delta t / \tau}$) to the residual eddy field from the previous time step, and adds the fresh eddy field contribution generated by the current gradient step. This new contribution is determined by multiplying the gradient step by its corresponding hardware coupling coefficient from the user-defined 9x3 matrix.
An example of this calculation is shown here:
```julia
    # Recursive integration
    for i in 2:N
        # Elapsed time between steps
        dt_elapsed = t[i] - t[i-1]

        # Helper to compute decay safely, avoiding division by zero / NaN
        decay(t_val) = (t_val == 0 || dt_elapsed == 0) ? zero(dt_elapsed) : exp(-dt_elapsed / t_val)

        # 0th- and 1st-order terms (Rows 1-4)
        Eb0[i] = Eb0[i-1]*decay(tau_vec[1]) + (dGx[i]*C[1, 1] + dGy[i]*C[1, 2] + dGz[i]*C[1, 3])

        # ... rest of spatial terms ...
```


***0th-Order Term*** 
The B0 eddy current term is baked into the existing $\Delta f$ array to save memory.
```julia
    Δf_final = seqd.Δf .- (Eb0 .* γ)
```
A 0th-order eddy current is fundamentally a spatially uniform perturbation to the static magnetic field over time ($\Delta B_0(t)$).
According to the Lamor equation ($\omega = \gamma B_0$), any global shift in the magnetic field translates directly into a global shift in precessional frequency. 
By multiplying the $B_0$ error field by the gyromagnetic ratio $\gamma$, we convert the error form Tesla to Hertz. Injecting this value directly into the pre-existing $\Delta f$ array therefore mirrors the physical reality of a global off-resonance.

***1st-Order Terms*** 
The X, Y, and Z linear eddy current terms are baked into the existing Gx, Gy, and Gz arrays, again to save memory and avoid unnecessary calculation.
```julia
    Gx_final = Gx .+ Ex
    Gy_final = Gy .+ Ey
    Gz_final = Gz .+ Ez 
```

***2nd-Order Terms*** 
The Z^2, ZX, ZY, XY, and X^2 - Y^2 2nd-order spatial cross terms have their own dedicated arrays Ez2, Ezx, Ezy, Exy, and Ex2y2 respectively.
These are returned in the new sequence to be used in calculations in the `BlochEddy` sim method.

The resulting modified sequence can then be used to simulate the effects of eddy currents in the Bloch equations.

### DiscreteEddySequence.jl
An extension of the base `DiscreteSequence` struct designed to accommodate higher-order spatial fields.
```julia
struct DiscreteEddySequence{

    # ... core parameters from DiscreteSequence struct ...

    # Add in eddy current params
    EZ2T<:AbstractVector{T},
    EZXT<:AbstractVector{T},
    EZYT<:AbstractVector{T},
    EXYT<:AbstractVector{T},
    EX2Y2T<:AbstractVector{T}
}

    # ... Standard fields ...

    # 2nd-order eddy current fields
    Ez2::EZ2T
    Ezx::EZXT
    Ezy::EZYT
    Exy::EXYT
    Ex2y2::EX2Y2T
end
```

## Execution
To run an eddy current simulation for a system, phantom and sequence combination of your choosing, you simply need to define your specific simulation parameters first i.e. the sim method, time constants, and coupling coefficients.

For example, consider a scenario where you aim to simulate a system with the following hardware imperfections:
- an XY eddy current term produced by the X gradient coil with $\tau = 50$ ms and a coupling coefficient of $0.05$, and
- a Z linear eddy current produced by the Y gradient coil with $\tau = 70$ ms and a coupling coefficient of $0.03$.
This could be achieved as follows (for predefined `sys`, `seq`, and `phantom` variables):
```julia
# Define hardware parameters
tau = zeros(9) # empty vector
tau[8] = 50e-3 # 50 ms decay constant for XY harmonic 
tau[4] = 70e-3 # 70 ms decay constant for Z harmonic 

coeffs = zeros(9, 3) # empty array
coeffs[8, 1] = 0.050 # X-gradient driving the XY cross-term
coeffs[4, 1] = 0.030 # Z-gradient driving the Z cross-term

# Simulation parameters
params_eddy = Dict{String, Any}(
    "return_type" => "raw", 
    "sim_method" => BlochEddy(),
    "tau" => tau, 
    "coeffs" => coeffs
)

# Run simulation
raw_eddy = simulate(phantom, seq, sys; sim_params = params_eddy)
```
